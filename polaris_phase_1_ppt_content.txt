POLARIS: AI-POWERED BEHAVIORAL TELEMETRY AND DIGITAL WELL-BEING ECOSYSTEM

Page 2: Problem Statement(s)
• Define the Problem: 
 Students and professionals are increasingly struggling with continuous digital distractions, mindless content consumption (doom-scrolling), and fragmented attention spans, which severely degrades their overall productivity and mental well-being.
• Context and Background: 
 Current digital environments and basic website blockers lack a unified, intelligent system that tracks deep, actionable behavioral metrics. While simple blockers restrict URLs, they fail to track granular data such as active viewport focus, infinite scroll depth, and contextual platform usage (like differentiating productive YouTube learning from distracted watching).
• Impact of the Problem:
 This lack of deep tracking results in decreased cognitive clarity, susceptibility to digital addiction, unquantifiable time loss, and an inability for users to make informed, data-driven decisions about their digital habits.

Page 3: Objective(s)
• Primary Objective: 
 Develop "Polaris" (Phase 1) — a comprehensive digital well-being ecosystem consisting of a data-collection Browser Extension and a centralized Web Dashboard for telemetry visualization and behavioral analysis.
• Secondary Objectives:
 1. Develop a Manifest V3 Browser Extension using background service workers for efficient, lightweight data collection.
 2. Implement deep, DOM-level tracking modules: Focus Tracker (viewport visibility), Scroll Tracker (pixel depth), YouTube Tracker (video state and engagement), and a Block Overlay for distraction mitigation.
 3. Develop a centralized React-based Web Dashboard to ingest, aggregate, and visualize the tracked metrics.
 4. Build a secure Python/FastAPI backend with JWT authentication, MySQL database, and real-time WebSocket support.
• Measurable Outcomes:
 1. Accurate, real-time logging of user focus states and scrolling behavior across active tabs.
 2. Seamless, secure data synchronization between the Browser Extension and the Web Dashboard via REST and WebSocket APIs.

Page 5: Literature Survey
Introduction
• The modern attention economy necessitates advanced digital productivity and well-being tools.
• Recent HCI (Human-Computer Interaction) research underscores the severe negative cognitive impacts of infinite scrolling and unstructured video consumption on dopamine regulation and sustained attention.
• Most existing commercial browser extensions provide rudimentary domain-level blocking but fundamentally lack granular behavioral tracking (e.g., they cannot tell if a user is actively reading a page or just leaving it open in the background).
• This survey systematically reviews recent frameworks (2025–2026) in web telemetry, digital well-being algorithms, and modern browser extension architectures to establish the technical foundation for Polaris.

Page 8: Advantages of Existing Work & Limitations
Advantages of Existing Work
• Low barrier to entry with simple installation and minimal configuration.
• Highly effective URL-based declarative blocking mechanisms.
• Gamified elements (e.g., Forest app) effectively encourage short bursts of focus.
Limitations
• Tracking is entirely surface-level: measuring absolute time spent on a domain rather than true active focus.
• Inability to contextually differentiate platform usage (e.g., watching a 2-hour educational lecture on YouTube vs. binge-watching short-form entertainment).
• Complete failure to track or quantify mindless infinite scrolling behavior, a primary driver of digital fatigue.
• No backend infrastructure for secure, persistent, user-specific data storage and analysis.

Page 9: Research Gap & Proposed Solution
Research Gaps
• Existing digital well-being systems lack deep, DOM-level tracking capabilities necessary for measuring scrolling distance and active viewport focus.
• There is a lack of a synergistic, real-time relationship between a lightweight data-collection agent (browser extension) and a comprehensive data-visualization platform (web dashboard).
• No existing tools combine AI-driven behavioral analysis with real-time WebSocket sync and a secure multi-user backend.
Proposed Solution
• The proposed Polaris System (Phase 1) addresses these gaps by engineering:
 1. A custom Manifest V3 Browser Extension featuring: blockOverlay.js, scrollTracker.js, focusTracker.js, contentScript.js, and youtubeTracker.js.
 2. A Python/FastAPI backend with MySQL database, JWT authentication, WebSocket manager, and dedicated routes for tracking, productivity, AI, and notifications.
 3. A React-based Web Dashboard that ingests this behavioral telemetry to provide actionable, data-driven insights.

Page 11: Existing Technology
• Current Solutions:
 1. RescueTime: Industry standard for general time tracking, but lacks granular scroll or interaction data and has no AI analysis layer.
 2. StayFocusd: Effective lightweight URL blocker, but offers zero data visualization, dashboarding, or backend capabilities.
 3. Apple Screen Time / Android Digital Wellbeing: OS-level, but lacks browser-specific contextual tracking (e.g., YouTube video states).
• Limitations of Current Tech:
 1. Inability to track "how" a site is used (actively reading vs. mindlessly scrolling).
 2. Disjointed experiences between data collection tools and analytics dashboards.
 3. No AI/ML layer for personalized behavioral insights.
• Technological Trends:
 1. Manifest V3 Extension standards for improved security and performance.
 2. Real-time WebSocket data synchronization.
 3. AI-powered behavioral analytics (LLM + Embeddings).

Page 12: Proposed Work / Methodology
• Concept and Approach: Phase 1 of Polaris is a cohesive digital well-being ecosystem, engineering a highly optimized data-collecting Browser Extension that feeds telemetry into a Python/FastAPI backend, visualized via a React Dashboard.
• Innovations:
 1. Custom JavaScript content scripts (scrollTracker, focusTracker, youtubeTracker, blockOverlay) capture deep DOM-level behavioral metrics natively within the browser.
 2. AI/RAG pipeline (OpenAI / Groq + Sentence Transformers + FAISS) for semantic behavioral analysis.
 3. Real-time data push via WebSocket manager for live dashboard updates.
• Feasibility: Developed using industry-standard, open-source technologies ensuring cross-platform browser compatibility, scalability, and ease of deployment.
 Tools and Techniques:
 1. Dashboard UI: React (Vite), Tailwind CSS
 2. Extension Architecture: Manifest V3, Background Service Workers, Content Scripts
 3. Backend: Python, FastAPI, Uvicorn
 4. Database: MySQL (SQLAlchemy ORM, Alembic migrations, PyMySQL)
 5. Authentication: JWT (python-jose, passlib, bcrypt)
 6. AI/ML: OpenAI API, Groq API, Sentence Transformers, FAISS
 7. Realtime: WebSockets

Page 13: Proposed Work / Methodology (Architecture Flow)
1. DATA INGESTION (EXTENSION): Modular content scripts dynamically load onto active browser tabs to track pixel-level scrolling (scrollTracker.js), page visibility/focus states (focusTracker.js), and specific YouTube video player states (youtubeTracker.js).
2. BACKGROUND PROCESSING: The Extension Service Worker (background.js) securely aggregates raw telemetry, manages local state, and handles declarativeNetRequest rules for site blocking.
3. DATA TRANSMISSION: Aggregated telemetry payloads are transmitted via REST API calls and live WebSocket connections to the FastAPI backend.
4. DATA STORAGE: The FastAPI backend processes and securely stores time-series activity logs in a MySQL Database via SQLAlchemy ORM, with schema managed by Alembic migrations.
5. AI ANALYSIS: The AI/RAG service (Groq/OpenAI + Sentence Transformers + FAISS) processes behavioral data to generate semantic insights and recommendations.
6. DATA VISUALIZATION (DASHBOARD): The React Dashboard fetches processed metrics to render interactive charts, focus scores, and detailed daily activity timelines.
7. USER CONTROL & FEEDBACK LOOP: Users configure custom blocklists and focus goals on the Dashboard, which sync back to the Extension via WebSocket.
